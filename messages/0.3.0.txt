# MarkdownGlance 0.3.0

The table of contents is opt-in now, the preview follows the colour scheme your
Markdown file resolved, and editing a large document costs a fraction of what
it did.

If you want the table of contents back, set it in Preferences → Package
Settings → MarkdownGlance → Settings:

    "enable_toc": true

It takes an editor group of its own, which is a lot to spend on a document you
did not ask it for. Closing it from its tab now also keeps it closed for that
preview instead of having it reappear a second later.

Colour. Every surface now sits on the scheme the Markdown file itself resolved,
so one picked with "MarkdownEditing: Select Color Scheme" wins over the global
"UI: Select Color Scheme", exactly as it does in the editor — a light scheme
over a dark editor no longer renders as a dark preview beside a light source.
Mermaid diagrams follow it too: on a dark scheme the request now asks for
Mermaid's dark theme on the preview's own background, instead of near-black
labels on a near-black page.

Speed. A repaint that changes nothing no longer relays out the whole document,
repainting the table of contents no longer spins the window's focus, and a run
of indentation in a code block is no longer one element per space — the HTML
for this project's own 69 KB design document falls from 296 KB to 178 KB and
from 9332 elements to 3558. "MarkdownGlance: Copy Diagnostics" now reports what
recent renders and paints actually cost.

The table of contents and the outline are also given the width their longest
heading needs rather than a fixed share of the window; drag the divider to take
that back, or set "auto_width" to false.
